# 分阶段检测与隔离通信

本页描述当前开发代码，正式发布状态以 CHANGELOG / Release 为准。

## 运行方式

- 首阶段仅读取真实亮度 `0x10` 和对比度 `0x12`，显示基本控制；完整能力、固件、型号适配与其他控制在后台逐屏补齐。基本通道对象保留，避免已经排队的滑块操作引用被替换的连接。
- 每个 Windows 逻辑显示连接使用一个 `FluentControl.DdcHost` 子进程；同一逻辑连接中的物理显示器共享该进程并顺序通信。基础发现最多两个连接并行，进阶阶段逐屏执行，在屏幕之间释放生命周期门控。
- 主程序只持有子进程与物理显示器索引，不持有 DXVA2 物理句柄。句柄由子进程创建和释放；进程间使用继承的标准输入/输出匿名管道，不开端口。
- 单次通信限时 8 秒。超时、进程退出或损坏响应会中止该连接的进程，旧客户端永久失效；下一次刷新建立新连接。绝不在原请求上自动重启并重发，写入已执行但响应丢失时同样如此。
- 子进程校验父 PID 和启动时间，父进程异常结束时退出。原生调用尚未完成时，不从另一线程销毁其句柄。个别驱动可能延迟操作系统终止进程，隔离不能保证修复内核驱动故障。
- 高级扫描前写 `%LOCALAPPDATA%\FluentControl\DdcRecovery\<连接哈希>.json`，完成后清除。上次中断的连接，下次保留基础控制并跳过高级扫描；设置中的「重新检测」显式重试。用户主动打开诊断仍会访问硬件。
- 子进程使用 C# / .NET 8，无 Electron / Node / USB 库。离线安装复用主程序已经携带的 .NET 运行时，只增加辅助程序及其配置文件。常驻进程有内存成本，尚未给出实体多屏机器上的内存和延迟承诺。

## 读写语义

普通非事件 VCP 读取对指定 Windows 传输错误最多尝试三次，间隔 50ms；不支持、断开、无效句柄不重试。每次返回真实应答，失败不伪造历史缓存为当前值。`0x02/0x03/0x52`、显式诊断和配对读取不使用自动重试，避免消费多次事件或改写实验含义。所有写入均一次发送；原有色温/场景有限写后回读仍然只重读，不重写。

能力缓存继续只保存稳定元数据，不保存当前值或原生句柄。配对兼容设置和自定义控件见 [osd-pairing.md](osd-pairing.md)。USB/HID 研究见 [usb-hid-adaptation.md](usb-hid-adaptation.md)。

## 来源与验证

设计参考 [Twinkle Tray](https://github.com/xanderfrangos/twinkle-tray/tree/fec2ef0e7a3ad94092f230faa4d6d7b87a0cf188) 的分阶段发现、独立通信进程、探测恢复与按错误分类的重试。参考版本许可证为 MIT（版权归 Xander Frangos）；本次为 FC 的独立 C# 实现，未引入其 Electron 运行时、型号规则数据或厂商 USB 指令。完整许可见该版本 [LICENSE](https://github.com/xanderfrangos/twinkle-tray/blob/fec2ef0e7a3ad94092f230faa4d6d7b87a0cf188/LICENSE)。

错误常量依照 [Microsoft Winerror.h 文档](https://learn.microsoft.com/windows/win32/com/com-error-codes-5)。不要把 `0xC026258C`（无效物理句柄）加入瞬时错误重试表。

逻辑测试使用真实子进程配合假设备后端验证超时、崩溃、不同连接隔离和不重发。`scripts/Test-DdcHost.ps1` 验证发布目录里的辅助程序可运行、拒绝不存在的句柄并退出，不向实体显示器发送任何写入。WinUI 回归使用模拟设备验证配对交互；这些检查不能替代用户 HKC/HWV 的实机验证。
