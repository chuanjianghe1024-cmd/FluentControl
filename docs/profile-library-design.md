# 配置组织重设计：场景、设备档案与预设库

状态：后续产品及数据迁移设计备忘录，最初以 v0.3.33 为基线；2026-10-10 校正实施状态。v0.3.50 已实现型号预设库、总配置独立快照、跨型号兼容性应用与离线参数保留；开发构建 0.3.52 进一步显示尚无预设的已连接型号。下述持久设备档案、引用式收藏夹、统一绑定流程及桌面内嵌社区等仍属后续设计，不应把整份方案视为已实现或重新实现已有功能。详细任务与验收统一维护在 [agent.md](../agent.md)，已交付变更见 [CHANGELOG](../CHANGELOG.md)。独立网站在 FluentControl-Web 仓库开发，尚未部署，不等于桌面社区界面已接入。

## 要解决的问题

目前一个 ControlProfile 既是“我现在要用的整套环境”，又是“某型号的参数预设”，还承担了导入对象；Group 同时表示用户分类和导入文件。结果是常用场景必须先找组、筛选改变切换范围、一次导入产生一个新容器、显示器不在线时容易被当成不存在。

设计原则：设备连接状态不决定配置是否存在；场景是日常操作对象，预设是可复用的参数，文件是运输载体，分类只是视图。

## 用户看到的四种对象

| 对象 | 解决什么问题 | 示例 | 生命周期 |
| --- | --- | --- | --- |
| 场景 | 一键切换我整套设备的状态 | 办公、修图、夜间、游戏 | 独立保存，包含多台显示器，也可包含当前音频和鼠标设置 |
| 显示器档案 | 这是我的哪一台屏幕 | 左屏 MateView、右屏 Dell、公司屏幕 | 跨重启、断开保留；在线/离线只是状态 |
| 显示器预设 | 某型号在某用途下的一套参数 | MateView 的夜间模式、某游戏调色 | 不绑定某台物理设备，可收藏、复制、分享、下载 |
| 配置包 | 一次搬运一批场景或预设 | MateView 游戏预设合集 | 是导入导出文件或社区发布包，不是必须逐层进入的文件夹 |

“场景集 / 收藏夹”仅是组织方式。一个场景可以属于多个收藏夹；删除收藏夹只取消组织关系，不删除场景本身。原来的 Group 迁移成收藏夹，组名和排序保留。

## 日常操作界面

保留显示器、声音、鼠标等现有控制页面，不把每次调亮度变成配置管理操作。顶部提供一个跨分组的场景选择器：当前场景、上一个、下一个、保存修改、另存为。下拉可直接搜索所有场景，收藏在前；每项显示名称、用途、屏幕数及连接状态，例如“办公 · 1/2 屏在线”。

桌面面板以同一个全局场景队列为准，紧凑显示“办公 · 1/2 屏”，左右直接切场景。已增加的分组箭头在当前版本继续工作；采用新配置库后，第二行可收起为可选的收藏夹入口，不要求用户先切组才能找到场景。

快捷键、托盘与桌面箭头默认遍历全部场景；在设置里可以明确改成“仅收藏”。查询条件和打开哪个收藏夹都不隐式改变快捷键范围。主界面显示当前切换范围，用户不需要猜下一项是什么。

手动拖动滑块后标记“办公 · 已修改”。“更新场景”更新本次可读的值；“另存为”生成新场景。两者均不能把离线状态解释为删除指令。

## 配置库：浏览与筛选

新增一个“配置库”入口，包含“我的场景 / 显示器预设 / 社区”三个页签。社区未接入前明确显示未连接，不伪造下载数、评分或上传成功。

页面上方常驻搜索框；下面是可清除的筛选标签：

- 应用 / 游戏：支持自由输入、已有标签建议、应用标识。
- 型号：可选“我的所有显示器”，包含离线档案；或者精确型号、型号名称。
- 品牌：可多选，允许未知厂商码或人工补充。
- 来源：本地创建、文件导入、社区下载。
- 状态：已收藏、可全部应用、可部分应用、未绑定设备。

不同维度之间 AND；同一维度的多个值 OR。型号和品牌必须对应同一个预设目标，不能用场景里两台不同屏幕分别凑出匹配。兼容性依据当前实际支持的参数，不把“同型号”直接等同于所有参数都可用。

搜索只改变列表，不切换硬件、不取消当前场景。一个明显的“清除筛选”按钮恢复列表；当前场景始终在顶部可见，不会因为不匹配过滤条件消失。查询结果可保存为智能收藏夹，例如“我的显示器 + 游戏”，不复制底层配置。

每张列表卡片只放：名称、应用标签、目标型号、来源、兼容状态。常用动作是“应用 / 加入场景 / 收藏”；导出、分享、编辑信息、删除放到更多菜单。工具栏支持多选、全选、批量导出，避免每项单独操作。

## 显示器档案与离线保留

设备档案保存本地 UUID、用户别名、型号与品牌、已观察到的身份信息、最后连接时间和能力摘要。硬件在线枚举只更新运行状态，不重建或清空档案。

场景保存显示器档案 UUID → 参数快照，不绑定 M1/M2 枚举顺序。M 编号和左/右名称是显示标签，换接口或重新排列屏幕不应自动改写配置归属。

识别按可信度匹配：先匹配可靠的本地硬件身份，再匹配已确认的连接别名。若两台相同型号无法可靠区分，提示重新认领“左屏 / 右屏”，绝不只凭同型号自动互换。序列号、设备路径等本地身份信息不上传。

示例：

| 场景“办公”的设备 | 状态 | 保存参数 | 应用结果 |
| --- | --- | --- | --- |
| 左屏 MateView | 在线 | 亮度 45、对比度 65 | 对可写项应用 |
| 右屏 Dell | 离线 | 亮度 30、色温预设 | 原样保留，显示“等待连接” |
| 公司屏幕 | 未绑定 | 从社区导入的一套参数 | 保留为未绑定目标，可稍后认领 |

应用场景后应区分“期望场景”和“实际结果”：显示“已应用 1/2 台，1 台离线”；单个失败也不能假装全部成功。离线是常态，不用每次用错误提示刷屏。展开详情再看失败、暂不支持及未绑定项目。

更新场景采用按字段合并：覆盖本次成功读取且可保存的值，保留离线屏幕、暂不可读/不可写项、别名、映射和来源。删除屏幕或某参数必须是独立的明确操作，并提供撤销或回收站。

重新连接时恢复身份关联并刷新能力。默认不自动发送硬件指令；可选“重新连接后应用当前场景”，仅在当前场景仍有效时恢复安全参数，不自动切输入源、电源或重置。旧请求不得覆盖用户后来选的新场景。

## 导入与下载共用一条流程

文件拖入、文件选择和社区下载进入同一个预览：有多少预设、多少场景、涉及哪些型号、重复项目以及匹配情况。下载后先保存到库，不要求马上插上对应屏幕。

默认动作是“添加到库”，另有“导入并应用”用于明确的一步应用。应用前仍检查兼容性及敏感输入切换。不要为每个文件强迫用户新建一组；可选创建一个同名收藏夹，导入批次本身作为来源记录。

设备绑定是可以跳过、以后修改的步骤：自动建议唯一可靠的匹配；同型号多个设备由用户确认；没有设备则保存成未绑定目标。一次映射可覆盖包里的多个模式，避免逐场景重复选择。

重复处理按稳定对象 ID、来源 ID、版本与规范化内容校验，不以名字作为唯一身份：

- 相同对象、相同版本与内容：跳过，报告数量。
- 上游新版本、本地未修改：允许显式更新。
- 上游新版本、本地已修改：保留本地并另存新版，展示差异。
- 仅名字相同：保留两个对象，以来源和编号区分。

导入或社区下载的单屏预设通过“加入场景”映射到任意已匹配的档案；加入时复制参数快照并记录来源版本，后续社区更新不会偷偷改变正在使用的场景。

## 导出、备份与上传

用同一套选择界面收集内容，但区分输出目的：

| 操作 | 默认内容 | 包含离线目标 | 包含本地设备身份 |
| --- | --- | --- | --- |
| 导出分享包 | 已选预设/场景的可分享显示器参数、型号、用途、应用标签 | 是 | 否，以公共 slot 代替 |
| 按型号导出合集 | 该型号已选或全部模式 | 是 | 否 |
| 备份全部 | 档案、场景、收藏夹、绑定、来源、本地设置 | 是 | 是，仅用于用户自己的本地备份 |
| 上传社区 | 与分享包相同的纯数据，另加发布信息与版本 | 是 | 否 |

中文名称用可读 UTF-8。默认显示器分享不带本机音频端点、设备序列号、路径、快捷键或启动设置。公开包与私人备份使用不同 schema，避免误传。

上传预览列出发布标题、型号/品牌、应用/游戏、用途标签和模式列表，可一次发布“一型号 × 多模式”。服务端应验证并派生索引，而非盲目信任上传标签。客户端明确显示需要登录与上传结果；未接入时只提供导出及接口预留。

## 数据落点与迁移

建议实体边界：

- `MonitorRecord`：本地持久身份、别名、型号、最后连接信息。在线句柄不序列化。
- `Scene`：稳定 ID、名称、应用/用途标签、多个设备参数快照，可选音频/鼠标部分、来源修订号。
- `MonitorPreset`：稳定 ID、适用型号、参数、应用/用途标签、来源与版本；不包含本机绑定。
- `Collection`：名称、排序、场景/预设 ID 引用；智能收藏夹存查询条件。
- `ImportBatch`：来源文件名或网址、时间、内容校验、对象映射，不决定用户导航层级。
- `DeviceBinding`：可分享目标 slot 与本机 MonitorRecord 的显式对应关系，允许未绑定。
- `ApplyResult`：本次设备/参数的已应用、离线、不可用或失败状态，与持久场景分离。

迁移不直接覆盖旧文件：先备份并离线转换到新版本，核对场景数、目标数、参数数及映射后原子替换；失败继续读取旧版。旧 Group 转普通收藏夹；已有参数、屏幕别名、亮度映射、应用标签、分组顺序全部保留。`unbound:` 目标迁移成显式的未绑定目标。v1/v2 文件仍通过适配器导入，新格式另起 schema/version。

实施顺序：先保住离线合并与数据身份，再把场景选择扁平化、分类改成引用式收藏夹；之后统一导入导出预览与可延后绑定，最后接入社区上传下载与版本差异。当前新增的分组切换功能属于过渡版本，不把它变成新架构的前置依赖。

## 验收场景

1. 两屏保存办公场景，拔掉右屏，修改左屏并更新、重启、导出；右屏的参数、名称、映射仍完整。
2. 显示器离线时下载其五个游戏预设；无需绑定即可保存，连接后一次认领并分别加入场景。
3. 两台同型号显示器换接口，不误换左右设置；无法可靠识别时保持未绑定待确认。
4. 搜索某游戏 + 某型号 + 品牌，列表按 AND 过滤，当前正在使用的场景及快捷键范围不改变。
5. 删除导入收藏夹，不删除其中场景；删除场景有明确操作与撤销。
6. 社区有新版，本地已改亮度；下载不会覆盖本地或改变硬件，允许保留两份或显式合并。
7. 切换到新场景后才连上旧场景涉及的屏幕，旧异步任务不能把新场景的参数覆盖。
