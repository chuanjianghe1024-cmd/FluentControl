# 双屏 HKC / 笔记本精简实机验收

状态：**流程已准备，尚未执行实机验证**。可用于 v0.3.92 基线及后续修复构建；分别填写版本与结果，不把后续构建结果记到旧 MSI。

## 开始前（约 3 分钟）

1. 保存工作，确认每块屏幕的物理按键可用。用 Windows「识别」与 FC 标记确认左右屏；用 A/B 记录 HKC2752、HKC2701 的实际位置，不能仅靠 M1/M2 或型号认领。
2. 记录 FC 版本/源码 SHA、MSI SHA-256、Windows build、GPU/驱动、每屏型号/固件、接口/扩展坞、分辨率/刷新率/缩放、扩展/复制、笔记本交流电/电池。固件或内屏型号读不到填未知。
3. 截图记录每屏 Windows HDR 设置、实体 OSD 的 HDR/场景/色温/亮度/对比度，记录夜间模式、ACM、ICC/校色加载器状态。先暂停竞争调色程序和自动切换；保留其原配置，不删除 ICC。
4. 备份 `%LOCALAPPDATA%\FluentControl\`，重点 `color-recovery.json`（若有）、`user-state.json` 和日志。恢复记录含设备身份，不公开上传原文件。若已有恢复提示，先解决旧会话再开始。

截图不等于 Gamma 测量，肉眼颜色变化也不能证明精确 Kelvin；可用固定白/灰渐变图辅助观察，并记录照片的固定曝光/白平衡。

## 用例（每次只操作一个目标）

| ID | 操作 | 预期与记录重点 | 失败时 |

| H2 | SDR 下应用 A 4500 K，再用 FC 开 HDR、关 HDR | 先恢复 A 的原曲线，再切 HDR；HDR 下软件色温不可用；关 HDR 后不重放 4500 K；B 保持原状态 | R1/R2；若恢复失败应阻止 FC 开 HDR |
| G1 | SDR、ACM 关闭、扩展模式：A 应用 4500 K、7500 K、6500 K、恢复；B 单独重复 | 只影响目标；6500 K 保留原基线；恢复不抹去原校色；记录驱动回读与可见效果，两者分开 | R2 |

| L1 | 调整一个普通滑条后立即刷新；重复应用总配置后立即刷新/HDR；随后轻度调整新界面 | 旧排队操作不跨刷新继续写；已在执行的操作可能先完成。无旧参数回跳、无错误目标。仅作人工竞态观察，确定性覆盖看模拟测试 | 停止并保存带时间戳日志，R1/R2 |
| T1 | 恢复原色后，拔插 A；改变主屏；扩展→复制→扩展，每次刷新 | 不能按屏幕顺序把 A 配置写到 B；复制输出软件色温禁用，扩展后重新判定。恢复前后设备身份可能变化，不强行套旧记录 | R1/R2 |

补充故障分支：双屏应用软件色温后断开 A，再正常退出，B 仍应恢复；A 的记录保留，接回后显式处理。睡眠/唤醒也应分别记录驱动是否自行重置曲线，不能假定行为一致。

## 安全恢复

**R1（HDR/信号异常）：** 停止 FC 操作；在仍可见的屏幕上打开 Windows 显示设置，按识别目标恢复原 HDR、扩展模式、分辨率和刷新率。必要时使用实体按键选回正确输入；持续无信号时接回原接口/扩展坞并重启。不要用未知 VCP、电源或出厂重置“救屏”。

**R2（偏色/恢复失败）：** 先恢复已记录的 SDR、ACM 和输出模式，暂停竞争调色程序，重新打开 FC 并读取。仅在身份及归属可确认时点击恢复原颜色；若提示外部变化，不强行覆盖。使用原来的校色加载器重载原配置，或注销/重启后核对；重启不保证恢复精确校色。保留恢复文件和日志，不手改、跨屏复制或删除记录，不把线性 Gamma 当作原始曲线。无法恢复则停止验收，提交脱敏日志。
