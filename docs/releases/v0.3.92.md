# FluentControl v0.3.92

**按屏调整色温、切换 HDR，让显示器读取更稳 · Per-display warmth, HDR controls and more resilient monitor discovery**

[中文](#中文) · [English](#english) · [项目介绍 / About](https://github.com/chuanjianghe1024-cmd/FluentControl#readme)

## 中文

本版汇总正式版 **v0.3.75** 之后的更新：新增系统软件色温、每屏 Windows HDR 开关和常驻限制提示，改进显示器读取与异常处理，并扩展本地 OSD 配对。你可以在同一个面板里分别调整每块屏幕的冷暖和 HDR 状态，也能更清楚地知道某项调节为什么可能无效。

### 1. 新增系统色温：不必依赖显示器的硬件色温预设

- 在单屏和整体控制中展开 **系统色温（软件）**，选择 **2500–10000 K** 后点击“应用”。每屏独立，移动滑条本身不会立即修改画面。
- 提供 **恢复原颜色**，恢复接管前的曲线；可将已确认的目标保存到本机总配置。软件色温与显示器 DDC 色温分别管理，不会改写硬件色温预设。
- 隐藏到托盘保留效果，正常退出时尝试恢复。异常退出后保留恢复记录，下次启动由你选择恢复；不会开机自动套用旧色温。
- 若其他程序或显示模式改变了颜色曲线，FC 停止接管，保留新的颜色设置，避免反复覆盖。

这是 **SDR 下的近似冷暖调节**，不是仪器校色。6500 K 保留接管前的曲线，不代表把屏幕校准到准确的 6500 K。HDR、自动颜色管理、复制屏幕共用输出或状态不明时禁用该兼容接口，并提供 Windows 夜间模式入口。请避免与其他调色、夜间模式或校色加载工具同时使用。[详细说明](https://github.com/chuanjianghe1024-cmd/FluentControl/blob/main/docs/system-color-temperature.md)。

### 2. 新增每屏 HDR 开关，并解释“为什么调不了”

- 单屏和整体视图均提供独立的 **Windows HDR** 开关；不依赖显示器 DDC/CI，内屏也按 Windows 报告的支持情况开放。
- 切换后核对 HDR 状态，再重新读取显示器控制项。不会自动重放此前的亮度、对比度或场景参数；通过 FC 开启 HDR 前会先尝试恢复自己正在使用的软件色温曲线。
- HDR 开启时，对应屏幕和 **FC 屏幕菜单** 显示常驻提示：亮度、对比度、色温等可能被显示器锁定；如果调节无效，可关闭 HDR 后重新读取。提示按屏幕显示，关闭并刷新后移除，仍支持调节的控制项保持可用。
- 区分“不支持”“受系统或电源策略限制”和“状态尚未确认”，不会把广色域/自动颜色管理误当成 HDR。

若在 Windows 或其他软件中切换 HDR，请在 FC 中重新读取设备。HDR 开关不加入总配置或开机动作；切换时画面可能短暂黑屏，实际可控项目仍由显卡、连接和显示器固件决定。[HDR 与笔记本控制说明](https://github.com/chuanjianghe1024-cmd/FluentControl/blob/main/docs/windows-hdr.md)。

### 3. 改进显示器读取，减少异常设备的影响

- **先显示基础控制，再补齐高级功能。** 亮度、对比度的实时结果可以先出现，不必等待全部高级能力查询完成。
- **隔离 DDC 通信。** 显示器通信放入独立辅助进程；超时后中止异常连接，刷新时重建，减少驱动或单台屏幕无响应造成的长时间等待。
- **避免反复卡在同一高级查询。** 中断后记录异常探测，下次可跳过；需要时仍可主动重新检测。
- 对部分普通读取的临时传输错误进行有限重试。配对试发和设置写入不会自动重发，读取失败也不会用历史值伪装成当前状态。

这些变化改善通信与反馈，不能让固件未提供的功能变成可用功能。[读取与异常处理说明](https://github.com/chuanjianghe1024-cmd/FluentControl/blob/main/docs/ddc-reliability.md)。

### 4. 增强本地 OSD 配对，保留更多已验证的操作

在上一版“试发指令、观察效果、绑定遥控”的基础上，新增：

- **自定义按钮和选项组。** 已确认的指令可以保存为自己命名的控件，在“遥控”页使用；同组选项可逐项添加经过验证的指令。
- **通信兼容设置。** 支持发送后等待 **0–2000 ms**，也可以关闭写后回读，以便调试打开菜单后不再正常响应读取的设备；每次试验记录当时采用的设置，效果仍由用户观察确认。
- **更完整的对比记录。** 可手动记录 HDMI、DP、USB-C 等视频连接方式，配合型号、固件、HDR 状态和试验结果比较同一屏幕的表现。
- 配对文件更新为 v3，仍可读取 v1/v2；导入不会自动激活自定义操作或覆盖本机通信设置。仍可完全离线完成，无需上传。

入口：**型号适配 → OSD 配对 / 遥控**。原厂菜单能打开，不代表支持远程方向键；未知指令仍需逐次试验并确认。本版没有内置通用 HKC/HWV 导航指令，也没有接入 USB/HID 控制。[本地配对说明](https://github.com/chuanjianghe1024-cmd/FluentControl/blob/main/docs/osd-pairing.md)。

## English

This release brings together the changes since **v0.3.75**: software color temperature, per-display Windows HDR switches and persistent limitation notices, more resilient monitor discovery, and expanded local OSD pairing. Adjust each screen's warmth and HDR state from one panel, with clearer feedback when the display restricts a control.

### 1. Software color temperature, independent of hardware presets

- Expand **System temperature (software)** in either display view, choose **2500–10000 K**, then click Apply. Each display is independent; moving the slider alone makes no change.
- **Restore original colors** returns to the captured curve. Save confirmed targets in local global profiles without changing DDC hardware color presets.
- The tray keeps the effect active; normal exit attempts restoration. An interrupted session retains recovery information for explicit restoration on the next launch. Saved temperatures are not automatically applied at startup.
- External curve changes release FC's control rather than triggering repeated writes over another program's settings.

This is an **approximate SDR warmth adjustment**, not measured calibration. 6500 K preserves the original curve. HDR, auto color management, duplicated outputs and unknown states block this compatibility interface and offer a Windows night light entry point. Avoid running competing color tools at the same time. See [scope and usage](https://github.com/chuanjianghe1024-cmd/FluentControl/blob/main/docs/system-color-temperature.md).

### 2. Per-display HDR switches and clearer control restrictions

- Switch **Windows HDR** independently in individual and overall views, including internal panels when Windows reports support. DDC/CI is not required for this switch.
- Verify HDR state and rediscover monitor controls after switching, without replaying old brightness, contrast or picture settings. Enabling HDR through FC first attempts to restore its active software color curve.
- A persistent notice appears for the affected display and in the **FC on-screen menu**: HDR may restrict brightness, contrast, color temperature and other controls. If adjustments have no effect, disable HDR and refresh devices. The notice disappears after HDR is off and devices refresh; supported controls remain usable.
- Distinguish unsupported HDR, system/power restrictions and unconfirmed state. Wide color gamut and auto color management are not treated as HDR.

Refresh devices in FC after changing HDR elsewhere. HDR is not saved in global profiles or startup actions. Switching may briefly blank the screen, and actual control availability depends on the driver, connection and firmware. See [HDR and laptop control notes](https://github.com/chuanjianghe1024-cmd/FluentControl/blob/main/docs/windows-hdr.md).

### 3. More resilient monitor discovery

- Show live brightness and contrast first, then load advanced features.
- Isolate DDC communication in helper processes. Stop a timed-out connection and rebuild it on refresh, reducing prolonged waits caused by unresponsive drivers or monitors.
- Remember interrupted advanced probes so they can be skipped next time; explicit redetection remains available.
- Retry selected temporary errors during ordinary reads, with bounded attempts. Never automatically resend settings or pairing commands, or present cached historical values as live readings.

These changes improve communication and feedback; they cannot add features absent from monitor firmware. See [discovery and recovery details](https://github.com/chuanjianghe1024-cmd/FluentControl/blob/main/docs/ddc-reliability.md).

### 4. More flexible local OSD pairing

Building on the previous release's command testing and observed-effect bindings:

- Save confirmed commands as **named buttons or choice groups**, available on the Remote page. Add verified options one at a time.
- Configure **0–2000 ms settling time** and optional post-write readback for devices that stop answering reads while their menu is open. Each trial records its settings; visual confirmation is still required.
- Manually record HDMI, DP, USB-C or another video connection alongside model, firmware, HDR and trial information for comparisons.
- Write v3 pairing files while retaining v1/v2 reading support. Imports do not activate custom controls or replace local communication settings. Pairing remains fully offline.

Open **Model adapters → OSD pairing / remote**. Opening the native menu does not prove remote navigation support. No universal HKC/HWV navigation commands or USB/HID control are included. See the [pairing guide](https://github.com/chuanjianghe1024-cmd/FluentControl/blob/main/docs/osd-pairing.md).
