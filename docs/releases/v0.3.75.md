# FluentControl v0.3.75

**在本机探索并配对显示器原厂菜单 · Explore and pair your monitor's native menu locally**

[中文](#中文) · [English](#english) · [项目介绍 / About](https://github.com/chuanjianghe1024-cmd/FluentControl#readme)

## 中文

本版新增实验性的本地 OSD 配对助手：让显示器声明支持、但用途未知的指令成为可试发的候选，由你观察实际效果并绑定成菜单操作。每台显示器都可以独立完成配对，无需登录、上传诊断或等待在线适配库。

### 本版更新

- **自动列出未知指令。** 从当前显示器的能力声明生成候选，代码和来源自动带出。有参数列表时直接提供声明值；只有代码时提供明确标为试验值的按钮，并允许填写其他值。每次点击只发送一次。已知标准功能、重置、频率、版本和事件通知另列用途。
- **按实际效果绑定遥控。** 先确认原厂菜单能打开，再试发候选；观察后绑定打开、关闭、上、下、返回、确认等动作。摇杆左、右可按实际效果映射为返回、确认。支持部分配对、重复操作和重新配对，未验证的动作保持不可用。
- **完整记录留在本机。** 保存型号、固件、能力信息、诊断基线、参数来源、发送与读回结果、观察和绑定。支持可选 JSON 导入导出；导入的候选需在当前显示器重新验证。重新配对会保留旧记录的本地归档。还可短时采集实体按键事件，辅助诊断。
- **处理打开菜单后的读回失败。** 配对窗口允许你明确选择沿用本次会话已读取的按键字段进行恢复测试；不会使用磁盘中的旧状态。禁用 OSD 与按键事件仍需二次确认。
- **修复 OSD 下拉框自动跳回。** 指令执行或取消后清空待发送选项，允许再次选择同一个操作；写入成功但读回失败时显示“已发送，状态未确认”。
- **色温和场景模式也可重复选择。** 待发送选项与真实读回值分别展示，避免旧状态阻止重试。写读不一致时保留原始结果；读回失败时不把旧值保存为新的设备快照。

### 开始配对

选择显示器，打开 **型号适配 → OSD 配对 / 遥控 → 测试已声明的未知指令**。确认菜单可打开，选择代码和值试发，展开“绑定观察到的动作”勾选实际效果，再确认结果。已绑定动作可在“遥控”页使用。详见[本地配对说明](https://github.com/chuanjianghe1024-cmd/FluentControl/blob/main/docs/osd-pairing.md)。

原厂菜单导航仍取决于型号和固件，未知指令不保证对应方向键。未声明参数的试验值可能改变未知设置；通信成功不等于菜单操作成功，需要你实机观察。若没有未知声明代码，界面会明确说明。此版本不代表已完成 HKC/HWV 全系列导航适配。

## English

This release adds an experimental local OSD pairing assistant. Unknown commands advertised by your monitor become explicit test candidates: observe what happens, then bind confirmed effects to menu controls. Each display can be paired independently without signing in, uploading diagnostics or relying on an online adapter catalog.

### What's new

- **Automatically discover unknown commands.** Candidates come from the current monitor's capability declaration, with codes and sources filled in. Advertised value lists become test buttons. Codes without value lists offer clearly labelled experimental values and an optional custom value. Each click sends once. Known standard features, resets, frequency/version queries and event notifications are classified separately.
- **Bind observed effects to a remote.** Confirm that the native menu opens, test a candidate, then bind open, close, up, down, back, confirm or other observed actions. Joystick left/right can map to back/confirm. Partial pairing, repeated commands and re-pairing are supported; unverified actions stay unavailable.
- **Keep evidence locally.** Save model, firmware, capabilities, diagnostic baselines, parameter provenance, write/readback results, observations and bindings. Optional JSON exchange retains evidence while requiring imported candidates to be tested on the current monitor. Re-pairing archives the previous record locally. Short read-only captures of physical button events support diagnosis.
- **Handle readback failure after opening the menu.** The pairing window offers explicit reuse of button fields successfully read during the current session for recovery tests. Saved historical values are not reused. Disabling both OSD and button events still requires a second confirmation.
- **Fix OSD selectors reverting to stale state.** The pending selection clears after execution or cancellation, so the same action can be sent again. A successful write with failed readback is shown as sent with unconfirmed state.
- **Allow repeated color-temperature and picture-mode selection.** Pending choices are separate from actual readback. Mismatches retain the raw result, and failed readback prevents stale values from being saved into new device snapshots.

### Start pairing

Select a monitor and open **Model adapters → OSD pairing / remote → Test advertised unknown commands**. Confirm that its menu opens, choose a code and value to test, expand Bind observed actions, select the actual effects and confirm the result. Use confirmed bindings on the Remote page. See the [local pairing guide](https://github.com/chuanjianghe1024-cmd/FluentControl/blob/main/docs/osd-pairing.md).

Native navigation depends on model and firmware; an unknown command is not necessarily a direction key. Experimental values without an advertised value list may change unknown settings. A successful transport response does not prove a menu action worked: observe the monitor. An empty candidate list is explained. This release does not claim complete HKC/HWV navigation support.
