# FluentControl v0.3.140

本次增加 USB 设备管理与 Wi-Fi 光照订阅。USB 数据连接即管理权限，无需绑定、账号或密码。

## 新增与改进

- FC 运行时提示新发现的兼容 USB 设备；在设置 → 自动调节中订阅和管理，默认不开启自动亮度。
- USB 设备设置提供 Wi-Fi 搜索、连接、取消、忘记网络、关闭/开启无线、重启及恢复出厂设置。设备按固件能力显示可用操作；RP2040 不提供 Wi-Fi。
- 配套 C3 参考程序连接新网络成功后才保存配置，失败或取消恢复旧配置。配置一次后，可仅接电源连接已保存的 Wi-Fi。
- USB 保存无线读取绑定，随后可发现同一局域网设备并订阅光照；请求及响应使用 HMAC-SHA256 认证。USB 管理不要求绑定，局域网没有管理写接口。
- 同一设备在 USB/Wi-Fi 间手动切换时保留订阅身份与历史；IP 改变后重新发现即可。明确指定 COM 端口时保留该端口选择。
- 安装包注册 `fluentcontrol://subscribe?device=<id>`，打开设备订阅页面，仍由用户确认添加。已有 FC 实例可接收链接。
- 加入通用数值信号规范，为其他传感器留出扩展方式；本版界面仍只消费光照。

## 安装与使用

使用下面的 Windows x64 Setup EXE（推荐）或 MSI；升级保留个人设置和安装目录。安装包未作 Authenticode 签名，校验值见 SHA256SUMS.txt。

设备管理要求新版板上程序。先备份旧程序，将 [main.py](https://github.com/chuanjianghe1024-cmd/FluentControl/blob/768fd670aab805833da8c28d9ee1a31bf3327e31/tools/light-source/device-v1/main.py) 和 [fc_device.py](https://github.com/chuanjianghe1024-cmd/FluentControl/blob/768fd670aab805833da8c28d9ee1a31bf3327e31/tools/light-source/device-v1/fc_device.py) 一起通过 Thonny 保存到对应 MicroPython 主板根目录，关闭 Thonny 后重启设备。RP2040 和 ESP32-C3 使用各自底层固件；按实物核对引脚，不能互刷 UF2。

FC → 设置 → 自动调节 → USB 设备设置与配网。C3 读取状态时保存本机无线绑定，配置网络成功后使用“发现已绑定的局域网设备”。主机保留最多 64 MiB 光照历史，硬件只有 64 条易失 RAM 缓存。完整接入方式见 [设备信号规范](https://github.com/chuanjianghe1024-cmd/FluentControl/blob/main/docs/device-signals.md)。

## 验证与未完成项

发布来源为提交 `768fd670aab805833da8c28d9ee1a31bf3327e31` 的 [Windows build #140](https://github.com/chuanjianghe1024-cmd/FluentControl/actions/runs/39218075603)。Windows 编译、控制逻辑、现有 WinUI 回归、MSI 及 Setup 验收通过；固件状态机有 13 项模拟测试。发布使用同次构建的安装包，未重新打包。

**实体 C3/RP2040 与 FC 完整联调、Wi-Fi 射频、真实显示器及混合 DPI 仍未验证。** C3 程序是参考实现，不能当作已验收的量产固件。需要保留机壳内部的烧录恢复能力。

BLE、热点配网、首次仅供电配网、FC 内刷写/OTA、自动切换 USB/Wi-Fi、通用多信号订阅界面和硬件历史回灌尚未实现。FC 未安装或未运行时，插入 USB 不会自动安装或启动软件；订阅链接需要安装版注册。无线读取通过 HTTP 认证但不加密读数；管理指令仅通过 USB。

---

This release adds USB device management and authenticated Wi-Fi light subscriptions. A physical USB data connection grants management authority without binding or login.

- Detect compatible USB arrivals while FC runs; subscribe and manage from Automatic adjustment settings without automatically enabling brightness control.
- Configure, cancel or forget Wi-Fi, enable/disable wireless, restart and reset supported devices over USB. Controls follow firmware capabilities.
- The C3 reference firmware saves new credentials only after connecting, restores old settings on failure/cancel, and reconnects saved Wi-Fi when powered without data.
- Save a wireless read binding over USB, then discover and subscribe on the LAN. Requests and replies use HMAC-SHA256; keys use Windows user-scoped DPAPI. LAN access is read-only.
- Preserve device/history identity when manually switching USB/LAN; rediscover after IP changes. Honor explicitly selected COM ports.
- Installer-registered subscription links open the device page for confirmation, including when FC is already running. Add an extensible numeric signal contract; the UI currently consumes illuminance only.

Install the offline x64 Setup EXE or MSI below. Upgrades preserve personal settings and installation location. Installers are unsigned; check SHA256SUMS.txt. Back up existing board code, copy both linked Python files into the correct MicroPython board filesystem, exit Thonny and restart. C3 provisioning starts with a USB data cable. FC stores up to 64 MiB of history; device caches are limited to 64 volatile readings.

Exact main build #140 passed Windows compilation, control-logic tests, existing WinUI regression and MSI/Setup validation; firmware state-machine tests cover 13 simulated cases. Physical C3/RP2040 integration, radios, monitors and mixed DPI remain unverified. C3 firmware is reference code, not production-validated firmware.

BLE, SoftAP/charge-only first provisioning, in-app firmware updates/OTA, automatic transport failover, generic multi-signal UI and device-history backfill are not implemented. USB insertion cannot install or start an absent/stopped FC automatically. LAN samples are authenticated over HTTP, not encrypted; all management uses USB. Keep internal recovery access.
