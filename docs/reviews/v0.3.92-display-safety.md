# v0.3.92 显示控制安全性与可靠性审查

审查日期：2026-10-12。发布基线：`b9785f4766c254cd8d138ff17687e4bf29678303`（`v0.3.92`）。修复基于 `084d06a` 的 main；已比较，发布基线到该 main 的 `src/` 和 `tests/FluentControl.Tests/` 没有变化。本文中的修复属于后续开发代码，不属于已发布 MSI；不移动旧标签或替换附件。

## 结论与发现

本次是有重点的代码审查与模拟回归，不是全面安全审计，也没有操作实体显示器。

### 1. 高：连续失败导致丢失 Gamma 恢复归属（已修复）

位置：发布版 `Services/SystemColor.cs` 的 `Set` / `Restore` / `Owned`。

复现：应用 4500 K，原生写入完成但回读抛错 → 当前曲线只记录在 Pending，Last 仍是原曲线 → 恢复原颜色将 Pending 改成 Original → 此次原生恢复写入失败 → 重启或只读刷新判定当前 4500 K 曲线为外部曲线并删除会话，原始基线失去自动恢复入口。原有测试只覆盖单次失败，没有覆盖“未确认写入 + 恢复失败 + 重启”。

修复：恢复前将刚读到、且已经核实归属的曲线保存为 Last，再记录新的 Pending。回归在未修复发布逻辑上明确失败于 `failed restore preserves ownership of previously pending curve across restart`，修复后恢复成功。

### 2. 中：总配置应用可跨越刷新或 HDR 切换继续执行（已修复）

位置：发布版 `MainWindow.Features.cs` 的 `ApplyProfileAsync`。

进入时不检查 hdrChanging；等待已有写入、输入确认和 gate 后也不检查 generation。与滑条、单屏色温、HDR、桌面回调不同，旧总配置请求可在拓扑刷新后继续解析当前通道并重放参数，违背 HDR 后不重放旧请求的约定。不是发现“已释放的物理句柄被直接使用”，而是旧用户意图被应用到刷新后的设备集合。

修复：入口阻止 HDR 切换期间启动，捕获 generation，在取得 gate 后再次校验刷新、HDR、退出及版本。新增 WinUI 模拟回归：持有 gate → 排队色温总配置 → 启动刷新 → 释放 gate，断言无颜色变更、无配置选择提交。该测试需要 Windows CI 执行，Linux 逻辑测试不包含此项。

### 3. 中：落盘和原生写入之间可能覆盖新的外部曲线（已加防护）

位置：发布版 `SystemColorService.Set/Restore` 与 `WindowsSystemColorBackend.Write`。

服务首次读取后会写恢复文件；后端写入前只复核身份和模式，不复核 LUT。若外部校色在此间完成，FC 会覆盖它。修复将期望曲线传给后端，在同一个 DC 上读取并比较，变化则拒绝调用 SetDeviceGammaRamp。应用与恢复两条路径均新增模拟注入回归，验证不写入且保留外部曲线。

剩余边界：GDI 没有原子比较并写入接口；最后一次读取与实际写调用之间仍存在竞争窗口。比较沿用现有每项 256 的量化容差，因此不能识别所有微小外部变化。不能宣称绝对杜绝与夜间模式、ICC 加载器或其他调色程序的竞争。

## 已审查的保护与边界

| 范围 | 源码证据 | 判断 |
| --- | --- | --- |
| HDR 身份 | `DisplayHdrController.Find/Set` 使用精确接口路径，不按型号、名称或顺序；写前重新枚举 LUID / TargetId | 零匹配、重复匹配、未知状态不写；同型号不共享目标。枚举到原生调用之间仍可能发生系统拓扑变化，不能由进程内 gate 完全排除 |
| HDR 双屏 | 控制器只向一个目标写一次；UI 整体视图仍保留每屏开关 | 模拟隔离已覆盖；真实驱动是否联动输出必须实测 |
| HDR 回读 | 12 次有限只读回读，区分 Enabled/Active，无重写 | 增加策略限制关闭/拒绝开启、未知状态和回读期间身份变模糊分支 |
| 刷新生命周期 | `RefreshAsync` 提前增加 generation；滑条/选择/桌面/高级扫描在 gate 下校验版本；HDR 在切换前失效旧版本，再重建 DDC | 总配置缺口见发现 2；已开始的原生操作不会被强制撤销，刷新等待其完成 |
| 正常退出 | `AppWindow.Closing` → `ExitWithColorRestoreAsync`，失效旧操作并等待 gate；`RestoreAll` 按屏捕获异常 | 隐藏托盘不恢复；不可达/HDR 屏保留记录且不阻止其他屏恢复，新增失败隔离回归 |
| 异常退出 | 构造函数只加载记录并标 Recovery；不自动写，用户恢复前核对令牌和曲线 | 新增连续失败恢复回归；新进程直接退出不会自动恢复旧会话 |
| HDR 与 Gamma | FC 开 HDR 前尝试恢复；异常阻止 HDR 调用；外部 HDR 使 Gamma 读写受阻，记录保留 | 外部曲线已改变时 Restore 返回 false 并放弃归属，HDR 可继续；HDR 关闭不自动重放色温 |
| SDR / 复制输出 | `LegacyGammaAllowed`、`SourceTargetCount == 1`、源名称和身份令牌检查 | 新增原生策略函数的独立 SDR、复制/缺失源、未知/HDR/ACM 模拟输入测试；真实拓扑枚举仍需复制输出、混合 GPU、热插拔实测 |
| 写入日志 | 写前持久化临时文件并替换；恢复数据有大小/结构限制 | 新增日志落盘失败不执行原生写入。现有实现没有显式 Flush(true)，不承诺突然断电时的磁盘耐久性 |
| OSD 配对 | 当前会话能力授权，逐次发送，用户观察才绑定；关闭/刷新后的 Active 校验；传输结果和观察结果独立 | 现有模拟测试覆盖；本次未新增私有指令或声称任何 HKC 导航已验证 |

正常退出恢复失败只写日志后退出，次次启动仍应保留可用记录；不能将“正常退出”解释为恢复必定成功。当前没有自动 HDR / 拓扑事件监听，外部变化后需手动刷新；Gamma 会话期间每 5 秒只读检查。
